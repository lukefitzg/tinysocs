# TS-062 — NTDS.dit / SYSTEM Hive Access

> Something tried to read the file that stores every password in your Active
> Directory domain.

## What it detects

A file-access event (Windows Security Event ID `4663`) touching `ntds.dit` or
the `SYSTEM` registry hive. One occurrence fires. On a domain controller,
`ntds.dit` is the database of every account's password hash; the `SYSTEM` hive
holds the key needed to decrypt it. Object-access auditing must be enabled on
those files for this to fire.

## Why it matters

Stealing `ntds.dit` is "game over" for a domain — it hands an attacker every
credential at once, enabling them to forge tickets and impersonate anyone,
including domain admins, indefinitely. It's the prize at the end of most
ransomware and espionage intrusions. A real hit here is a full-domain
compromise event; treat it as such.

## What a true positive looks like

Access to `ntds.dit` by a process other than the normal directory service
(`lsass.exe` / `ntdsutil.exe` during sanctioned maintenance) — often a copy via
`ntdsutil`, Volume Shadow Copy, or a backup tool being abused to grab the file
offline.

## Common false positives

- **Legitimate backups** of the domain controller read these files. Allowlist
  the backup host or the backup process:
  → allowlist `host: dc01-backup` or `process_path: C:\Program Files\<backup>\agent.exe`.
- **Sanctioned `ntdsutil` maintenance** by a domain admin. Allowlist the admin
  host during the maintenance window.

This rule honours these allowlist scopes (tune without editing the rule):

- `host`
- `host_pattern`

## Tuning knobs

None — single-event trigger. Reduce noise by allowlisting the known backup path,
never by raising a threshold.
