# TS-090 — Suspicious Service Installation

> A new Windows service was installed that runs from an unusual location like a
> temp or user folder — a common persistence trick.

## What it detects

A service-installation event (Windows System Event ID `7045`) where the service
binary lives in a suspicious path (temp, AppData, Public, or similar
non-standard locations). One occurrence fires.

## Why it matters

Windows services start automatically and run with high privilege, which makes
them a favourite way for attackers to keep a foothold across reboots. Legitimate
software installs services into `Program Files` or `System32` — not into a
user's temp directory. A service pointing at `C:\Users\Public\svc.exe` is almost
always either malware persistence or a dropper, not a real product.

## What a true positive looks like

A newly created service whose `ImagePath` points to AppData, a temp folder, the
Public profile, or a randomly named binary — often with a generic or misspelled
service name, appearing without any corresponding software installation.

## Common false positives

- **Poorly packaged legitimate software** or in-house tools that install
  services to non-standard paths. Allowlist the specific service name or its
  host once verified:
  → allowlist `event_data.ServiceName: AcmeAgent` or `host: lab-build01`.
- **Developer tooling** running services from project directories. Allowlist the
  dev hosts:
  → allowlist `host_pattern: dev-*`.

This rule honours these allowlist scopes (tune without editing the rule):

- `host`
- `host_pattern`

## Tuning knobs

None — single-event trigger keyed on path. Allowlist the specific benign service
rather than relaxing the path check.
