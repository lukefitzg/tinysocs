# TS-061 — Credential Dumping Tools

> A program with the name of a known password-stealing tool (Mimikatz, ProcDump,
> and friends) just started on this machine.

## What it detects

A process-creation event (Windows Security Event ID `4688`) where the new
process name contains one of a fixed list of credential-dumping tools:
`mimikatz`, `procdump`, `nanodump`, `pwdump`, `gsecdump`, `wce.exe`,
`sqldumper.exe`, `dumpert`, `lsassy`. One occurrence is enough to fire — there
is no "burst" threshold, because none of these tools have a legitimate reason to
run on a typical SMB endpoint.

It does **not** rely on command-line auditing (which is often disabled); it
matches on the process name alone, so it works on a default Windows audit
policy.

## Why it matters

Credential dumping is the hinge of almost every real intrusion. Once an attacker
has a foothold on one machine, dumping the credentials cached in memory (LSASS)
or on disk lets them move laterally and escalate — turning one compromised
laptop into a domain-wide problem. If this fires for real, assume the attacker
is mid-intrusion, not at the start. This is a wake-someone-up alert.

## What a true positive looks like

`procdump.exe` or `mimikatz.exe` launched on a workstation that has no business
running developer or sysadmin tooling, often spawned by an unusual parent
(a script, `cmd.exe` from a service account, or a freshly-created process). The
account is frequently a service or admin account being abused, not the
logged-in user.

## Common false positives

- **Sysinternals ProcDump used legitimately by IT** for crash diagnostics.
  `procdump` is a genuine Microsoft tool. If your admins use it, allowlist the
  specific account or the install path:
  → allowlist `user: itadmin` or `process_path: C:\Tools\procdump.exe`.
- **`sqldumper.exe` shipped with SQL Server** runs during some crash/dump
  workflows. On a DB host, allowlist it by path:
  → allowlist `process_path: C:\Program Files\Microsoft SQL Server\...\sqldumper.exe`.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`
- `user`

## Tuning knobs

None — single-event trigger. The detection is the *name match*, not a count, so
there is no threshold to tune. To reduce noise, allowlist the specific benign
case rather than weakening the rule.
