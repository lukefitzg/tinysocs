# TS-070 — PsExec Usage

> A new Windows service was installed that looks like PsExec — a tool commonly
> used to run commands on this machine from another one.

## What it detects

A service-installation event (Windows System Event ID `7045`) matching the
PsExec service-creation pattern. One occurrence fires. PsExec installs a
temporary service to execute its payload, which is what this catches.

## Why it matters

PsExec is a legitimate Sysinternals admin tool — and a favourite of attackers
for exactly the same reason: it runs commands on remote machines using stolen
credentials, which is how an intrusion spreads from the first compromised host
to the rest of the network. Seeing PsExec land on a machine that admins don't
normally manage that way is a strong lateral-movement signal.

## What a true positive looks like

A `PSEXESVC`-style service appearing on a workstation or server that your IT team
doesn't routinely administer with PsExec, especially shortly after a credential-
theft alert elsewhere, or originating from an unexpected host.

## Common false positives

- **IT legitimately uses PsExec** for remote administration and scripting. If
  so, allowlist the machines they manage this way, or the admin host pattern:
  → allowlist `host_pattern: ws-eng-*` for engineering machines IT admins via PsExec.
- **RMM / deployment tooling** that wraps PsExec-like service execution.
  Allowlist the managed hosts.

This rule honours these allowlist scopes (tune without editing the rule):

- `host`
- `host_pattern`

## Tuning knobs

None — single-event trigger. If PsExec is part of normal ops, allowlist the
specific hosts rather than disabling the rule; you still want to know when it
appears somewhere unexpected.
