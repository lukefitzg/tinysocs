# TS-135 — LOLBin Proxy Execution

> Trusted built-in Windows tools (rundll32, regsvr32, mshta, wmic, certutil)
> were used repeatedly — a way to run malicious code while looking legitimate.

## What it detects

Process-creation events (Windows Security Event ID `4688`) where the new process
is one of a set of "living-off-the-land" binaries — `rundll32.exe`,
`regsvr32.exe`, `mshta.exe`, `wmic.exe`, `certutil.exe` — grouped by process
name, firing at `3` occurrences within a `5`-minute window.

## Why it matters

These are signed, trusted Microsoft binaries ("LOLBins") that can be coaxed into
running attacker code, downloading payloads, or proxying execution — so the
malicious activity wears a trusted face and slips past allowlisting that only
blocks unknown executables. A burst of them is a common sign of a script or
loader chaining built-in tools to stage an attack without dropping obvious
malware.

## What a true positive looks like

Several of these binaries firing in quick succession — e.g. `mshta` pulling a
script, `rundll32`/`regsvr32` executing a payload, `certutil` decoding or
downloading a file — often spawned by an Office app, a script host, or each
other, on a machine where that combination makes no sense.

## Common false positives

- **Legitimate software and IT scripts** genuinely use these tools (`rundll32`
  for control-panel applets, `certutil` for cert management, `wmic` in admin
  scripts). On a busy admin or build host this can fire benignly — allowlist the
  host or the parent context:
  → allowlist `host_pattern: it-admin-*`.
- **Management / deployment tooling** that batches these calls. Allowlist the
  managed hosts.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`

## Tuning knobs

`threshold` (default `3`, range `1`–`15`). Raise it on admin hosts where these
tools are used legitimately in batches; lower it on standard user workstations
where any LOLBin burst is suspicious.
