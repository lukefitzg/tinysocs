# TS-113 — Mass File Modification (Ransomware Indicator)

> A huge number of files were changed on one machine in seconds — the classic
> fingerprint of ransomware encrypting everything it can reach.

## What it detects

File-modification events from the TinySOCs File Integrity Monitoring subsystem
(internal channel `TinySocs-FIM`, Event ID `1002`) grouped by host. The rule
fires when one machine logs more than `50` file modifications within a single
`1`-minute window. Unlike most rules, the source here is the agent's own FIM
watcher emitting synthetic events, not raw Windows logs.

## Why it matters

Ransomware's encryption phase touches hundreds or thousands of files in a very
short time — far faster and broader than any normal application. By the time a
human notices files won't open, the damage is done. A mass-modification spike is
one of the few signals that can fire *during* encryption, early enough to pull
the machine off the network and limit the blast radius. This is the highest-
urgency alert in the base pack.

## What a true positive looks like

A near-vertical burst of modifications across many directories on one host,
often with files gaining a new uniform extension (`.locked`, `.encrypted`, a
random string) and ransom-note files appearing. The originating process is
frequently something that has no business touching user documents en masse.

## Common false positives

- **Backup, sync, or AV full-scan jobs** that rewrite or touch large file sets.
  These run on a schedule from a known process — allowlist that process so its
  legitimate sweeps don't fire:
  → allowlist `process_path: C:\Program Files\Veeam\...\agent.exe`.
- **Bulk software deployment / OS update** rewriting `Program Files`. Allowlist
  the host during a known maintenance window, or the deploying process path.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`
- `host`

> Be conservative allowlisting this one. A too-broad allowlist here can blind
> you to real ransomware. Prefer scoping to a specific process path over a whole
> host.

## Tuning knobs

`threshold` (default `50`, range `12`–`250`) and the `1`-minute window. Raise
the threshold on file servers where large legitimate batch operations are
routine *and* allowlisting the responsible process isn't practical. Lowering it
increases sensitivity at the cost of more backup-job noise.
