# TS-133 — Process Injection (CreateRemoteThread)

> One program forced its code to run inside another program's memory — a stealth
> technique to hide malicious activity inside a trusted process.

## What it detects

A Sysmon CreateRemoteThread event (Event ID `8`), grouped by the source process
(`SourceImage`), firing on first occurrence. Requires Sysmon. CreateRemoteThread
is the classic API for injecting a thread into another process.

## Why it matters

Process injection lets malware run inside a legitimate, trusted process
(`explorer.exe`, `svchost.exe`, a browser) so its network connections and
actions appear to come from that trusted program — evading both the user and
naive security tools. It's a hallmark of more capable malware and post-
exploitation frameworks (Cobalt Strike, Metasploit). Seeing an unexpected
process inject into another is a strong defence-evasion signal.

## What a true positive looks like

An unusual or unsigned source process creating a remote thread in a system or
user process it has no reason to touch — often a freshly spawned binary, a
script host, or a renamed executable injecting into `explorer.exe` or
`svchost.exe`.

## Common false positives

- **Security products, debuggers, and some legitimate software** use remote-
  thread injection for valid reasons (AV, EDR, accessibility tools). Allowlist
  the known-good source process:
  → allowlist `process_path: C:\Program Files\<EDR>\sensor.exe`.
- **Developer / debugging tooling** on engineering machines. Allowlist those
  hosts:
  → allowlist `host_pattern: dev-*`.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`
- `user`

## Tuning knobs

None — single-event trigger. Allowlist the specific benign injectors (your
EDR/AV) rather than disabling; the unexpected injector is the point.
