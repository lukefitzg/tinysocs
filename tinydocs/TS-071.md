# TS-071 — RDP Brute Force

> Someone is repeatedly failing to log in over Remote Desktop from one address.

## What it detects

Failed-logon events (Windows Security Event ID `4625`) for Remote Desktop
(`LogonType` 10), grouped by source IP, firing at `10` failures within a
`10`-minute window. It's a tighter, RDP-specific cousin of TS-002 with a lower
threshold, because internet-exposed RDP is one of the single most-attacked
surfaces in SMB environments.

## Why it matters

Exposed RDP is the classic ransomware front door. Automated bots scan the
internet for port 3389 and brute-force credentials around the clock. A
successful guess hands an attacker an interactive desktop session as that user —
the start of the majority of hands-on-keyboard intrusions against small
businesses. Early detection (and ideally getting RDP off the public internet)
matters enormously.

## What a true positive looks like

A burst of RDP `4625` failures from an external IP, often against
`Administrator` or common usernames, frequently from a hosting/VPS provider or
foreign geography. If followed by a `4624` LogonType 10 success, escalate
immediately — the guess landed.

## Common false positives

- **A user with an out-of-date RDP credential** (saved in an RDP client or a
  reconnecting session) retrying from a known host. Allowlist their workstation:
  → allowlist `source_ip: 10.0.5.12`.
- **An internal jump host or admin console** doing legitimate bulk RDP.
  Allowlist its range:
  → allowlist `source_ip_cidr: 10.10.0.0/24`.

This rule honours these allowlist scopes (tune without editing the rule):

- `source_ip`
- `source_ip_cidr`

## Tuning knobs

`threshold` (default `10`, range `3`–`50`). Keep it low if RDP is exposed; the
stronger fix is to remove public RDP exposure entirely (VPN / RD Gateway).
