# TS-130 — Account Discovery

> Someone ran a burst of commands to enumerate the accounts and groups on this
> machine — the reconnaissance an attacker does after breaking in.

## What it detects

Process-creation events (Windows Security Event ID `4688`) for account-
enumeration binaries — `net.exe`, `net1.exe`, `whoami.exe`, `nltest.exe`,
`dsquery.exe`, `quser.exe`, `query.exe` — grouped by the running account, firing
at `5` occurrences within a `5`-minute window. It matches on process name (not
command line), so it works without command-line auditing.

## Why it matters

Right after gaining access, attackers orient themselves: who am I, what accounts
and groups exist, who's a domain admin, who else is logged in. A flurry of
these built-in discovery commands in a short window is a classic post-
compromise reconnaissance pattern. Individually the commands are harmless and
common — which is why this is a medium-severity *burst* rule, not a single-event
alert.

## What a true positive looks like

A rapid sequence of `whoami`, `net user`, `net group "Domain Admins"`,
`nltest /domain_trusts` and similar from one account — especially a service
account or a user who doesn't normally run admin commands, shortly after a logon
from an unusual source.

## Common false positives

- **Administrators and IT scripts** legitimately run these constantly. This is
  the main noise source. Allowlist the admin accounts or hosts:
  → allowlist `user: itadmin` or `host_pattern: it-admin-*`.
- **Login scripts and inventory/monitoring tools** that enumerate accounts on a
  schedule. Allowlist the service account running them:
  → allowlist `user: svc-inventory`.

This rule honours these allowlist scopes (tune without editing the rule):

- `user`
- `user_pattern`
- `host`

## Tuning knobs

`threshold` (default `5`, range `1`–`25`). Raise it for admin accounts that run
these tools in bulk (or better, allowlist those accounts); lower it on standard
user machines where a discovery burst is unexpected.
