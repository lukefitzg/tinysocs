# TS-081 — Windows Defender Tampering

> Windows Defender's protection was turned off, or a folder was excluded from
> scanning — a common move to let malware run undisturbed.

## What it detects

A Windows Defender operational event (Event ID `5001`) indicating real-time
protection was disabled or an exclusion was added. One occurrence fires.

## Why it matters

Before running their payload, attackers routinely weaken or blind the built-in
antivirus — disabling real-time protection or adding their working directory to
the exclusion list so their tools won't be scanned. On SMB endpoints where
Defender is often the *only* AV, tampering with it removes the last automated
line of defence. This frequently precedes ransomware deployment.

## What a true positive looks like

Real-time protection disabled, or an exclusion added for a suspicious path
(`C:\Users\Public`, a temp folder, a freshly created directory), by a process or
account that isn't your management tooling — often via PowerShell
(`Set-MpPreference`) or registry edits.

## Common false positives

- **Legitimate AV management** — if you deploy a third-party AV, it may disable
  Defender by design. Allowlist the management host or the deploying process:
  → allowlist `host: epmgmt01` or `process_path: C:\Program Files\<AV>\setup.exe`.
- **Developer / build machines** with sanctioned exclusions for performance.
  Allowlist those specific hosts:
  → allowlist `host_pattern: build-*`.

This rule honours these allowlist scopes (tune without editing the rule):

- `host`
- `host_pattern`

## Tuning knobs

None — single-event trigger. Allowlist the sanctioned management host rather
than disabling the rule; unexpected Defender tampering is exactly the signal you
want.
