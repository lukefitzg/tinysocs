# TS-114 — Sensitive System File Deleted

> A critical Windows security file (a password hive like SAM, SECURITY, or
> SYSTEM) was deleted.

## What it detects

A file-deletion event from the TinySOCs FIM subsystem (internal channel
`TinySocs-FIM`, Event ID `1003`) for a monitored sensitive file — the SAM,
SECURITY, or SYSTEM registry hives and similar. One occurrence fires.

## Why it matters

These files are the foundations of local authentication and the operating
system's integrity. Deleting them is either destructive sabotage (denial of
service / wiper behaviour) or an attempt to cover tracks after copying them for
offline credential cracking. Either way it's a high-impact action with no benign
explanation during normal operation — a critical-severity event.

## What a true positive looks like

Deletion of a SAM/SYSTEM hive or other monitored security file outside any
imaging or recovery operation, often alongside other destruction or credential-
access activity. On a server or DC this is especially alarming.

## Common false positives

- **OS reinstall / imaging / disaster-recovery** legitimately removes and
  rebuilds these files. Allowlist the imaging host or the recovery window:
  → allowlist `host_pattern: imaging-*`.
- **Sanctioned backup-and-restore tooling** that manipulates hives. Allowlist
  the specific tool's path:
  → allowlist `process_path: C:\Program Files\<backup>\restore.exe`.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`
- `host`

## Tuning knobs

None — single-event trigger. Given the severity, scope allowlists tightly
(specific process path or imaging host), never a blanket exclusion.
