## Per-miss analysis

The five misses split into three categories. Only one represents a genuine detection content gap.

### Category A — test payload structurally cannot trip a correctly-tuned production rule

These were test-fidelity gaps, not weak content. Each test has been replaced with one that faithfully reproduces the attack the rule targets.

- **T1110.001 (TS-001 brute-force)** — old fallback ran 6 attempts across 6 distinct usernames. TS-001 thresholds 15 by `TargetUserName`; TS-002 thresholds 20 by `IpAddress`. One event per by-account group, six per by-IP group. The test couldn't reach either threshold. **Fix:** hammer a single non-existent account 18× (faithful password-guessing). Spot-check 2026-06-06 → DETECTED in 219s.
- **T1059.001 (TS-030 / TS-082 PowerShell)** — old fallback ran benign `Write-Host`/`Get-Process`. TS-030 requires 200 scriptblocks; TS-082 requires AMSI-bypass signature. Neither exercised. **Replacement:** canonical AMSI-bypass reflection one-liner. Spot-check 2026-06-06 → Defender real-time protection blocks AMSI-bypass scripts at AMSI scan, before scriptblock logging captures them. Reclassified as **SKIP** (environmental constraint: requires Defender RTP disabled). Honest "can't test this here" — analogous to existing Sysmon SKIPs.

### Category B — harness ran the wrong workload (false-miss in disguise)

The rules fire reliably when the right workload runs. The Atomic Red Team atomics either don't exist for the technique on Windows, or run a workload that doesn't exercise the TinySocs rule.

- **T1018 (TS-131 Remote System Discovery)** — ART's T1018-1 atomic runs `net view`, spawning `net.exe`. That exercises TS-130's account-discovery field_match, not TS-131's network-discovery field_match. The faithful fallback (ipconfig/netstat/arp/route/netsh/nbtstat × 2 = 12 events) never ran because ART didn't fail. Direct diagnostic on 2026-06-06 confirmed: running the fallback by hand produced alert `TS-131|lukefitzgerald|2026-06-06T10:15:00Z` (event_count=4) in the index. **Fix:** `prefer_fallback: true` on T1018. Spot-check 2026-06-06 → DETECTED in 16.5s.
- **T1218.011 (TS-135 rundll32)** — same pattern, intermittent: ART's atomic sometimes fails "Access is denied" (fallback runs, detect), sometimes succeeds with a single rundll32 spawn that doesn't reach threshold 3 (miss). **Fix:** `prefer_fallback: true` on T1218.011. The faithful fallback (5× harmless rundll32 via `user32.dll,UpdatePerUserSystemParameters`) reliably clears threshold with margin. Spot-check 2026-06-06 → DETECTED in 17.5s.

### Category C — genuine rule design gap

- **T1105 (TS-132 Ingress Tool Transfer)** — TS-132 uses `group_by: NewProcessName` + `threshold: 2`. A realistic single `certutil` or single `bitsadmin` download produces one event per binary, so the group counter never reaches 2. A faithful test (1× bitsadmin + 1× certutil) correctly exposed this: a single-use LOLBin download evades TS-132. **Decision deferred to next content cadence:** retune TS-132 to `threshold: 1` with command-line `field_match` for download indicators (`urlcache`, `/transfer`, `http://`, `https://`). Catches single-use downloads while suppressing benign cert-management operations. Requires its own validation pass before shipping.

## Open items for follow-up

- **TS-132 rule tuning.** Genuine content gap. Proposed change documented above. Needs its own Atomic test + validation pass before shipping.
- **T1105 fallback hang.** The bitsadmin fallback can hang indefinitely on slow networks (observed 2026-06-06). Add explicit `bitsadmin /reset` + `/cancel` timeout, or replace with a faster downloader. Doesn't affect the efficacy number (TS-132 misses regardless) but affects harness runtime.
- **VM sleep contamination.** A mid-run hibernation event in 2026-06-06's warm-run attempt produced unusable timing data and false misses. Disabled via `powercfg /change standby-timeout-*` and Parallels "Pause when idle" off. Document in the runbook.
