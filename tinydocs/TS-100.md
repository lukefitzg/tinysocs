# TS-100 — DNS Tunnelling Volume

> A machine made an unusually large number of DNS lookups for the same domain —
> a sign data is being smuggled out through DNS.

## What it detects

Sysmon DNS-query events (Event ID `22`) grouped by queried domain, firing when
one domain receives more than `200` queries within a `10`-minute window.
Requires Sysmon DNS logging.

## Why it matters

DNS almost always works even when other outbound traffic is blocked, so
attackers abuse it as a covert channel — encoding stolen data or command-and-
control traffic into a flood of subdomain lookups against a domain they control.
Normal applications resolve a domain a handful of times and cache it; hundreds of
lookups to one domain in minutes is the fingerprint of tunnelling, not browsing.

## What a true positive looks like

A high volume of lookups to a single (often long, random-looking, or recently
registered) domain, with constantly changing subdomains (the encoded payload),
from a host that has no business talking to that domain.

## Common false positives

- **Legitimate high-volume DNS** from telemetry, CDNs, security products, or
  monitoring agents that genuinely query a vendor domain frequently. Allowlist
  the known domain:
  → allowlist `event_data.QueryName: telemetry.vendor.com`.
- **A busy mail or web server** with heavy legitimate resolution. Allowlist the
  host if its volume is understood:
  → allowlist `host: mail01`.

This rule honours these allowlist scopes (tune without editing the rule):

- `host`
- `event_data.QueryName`

## Tuning knobs

`threshold` (default `200`, range `50`–`1000`) and the `10`-minute window. Raise
it on servers with legitimately chatty DNS once you've allowlisted known vendor
domains; lower it on quiet workstation fleets for more sensitivity.
