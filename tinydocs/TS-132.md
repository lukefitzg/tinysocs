# TS-132 — Ingress Tool Transfer

> A built-in Windows downloader (`certutil` or `bitsadmin`) was used — a common
> way attackers pull their tools onto a machine.

## What it detects

Process-creation events (Windows Security Event ID `4688`) for `certutil.exe` or
`bitsadmin.exe`, grouped by process name, firing at `2` occurrences within a
`5`-minute window (with a 30-minute cooldown). These are signed Windows tools
that can download files from the internet.

## Why it matters

After getting an initial foothold, attackers need to bring in their actual
toolkit — and rather than risk a flagged custom downloader, they abuse trusted
built-ins like `certutil` (designed for certificates, but happily downloads any
file) and `bitsadmin`. Seeing these used as downloaders, especially fetching
from an external URL, is a recognised sign of an intrusion moving from foothold
to tooling-up.

## What a true positive looks like

`certutil -urlcache -f http://...` or `bitsadmin /transfer` pulling an
executable or script from an unfamiliar URL, on a machine where these tools
aren't part of normal admin work, often shortly after another suspicious event.

## Common false positives

- **Legitimate certificate management** genuinely uses `certutil` (without the
  download flags). And some IT scripts use `bitsadmin` for transfers. On admin
  hosts this can be benign — allowlist them:
  → allowlist `host_pattern: it-admin-*`.
- **Software updaters** built on BITS. Allowlist the specific managed hosts if
  it proves noisy.

This rule honours these allowlist scopes (tune without editing the rule):

- `process_path`
- `process_pattern`

## Tuning knobs

`threshold` (default `2`, range `1`–`10`). On admin machines where these tools
see legitimate use, raise it; on standard workstations keep it low — a download
via `certutil` there is rarely benign.
